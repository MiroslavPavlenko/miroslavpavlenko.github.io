Doubling data

  • T(N) = a·Nb → T(2N)/T(N) = 2b. a cancels, so the machine drops out.
  • Ratio 2 → N · just over 2 and falling → N log₂ N · 4 → N² · just over 4 → N² log₂ N · 8 → N³.
  • Any factor: b = log(T₂/T₁) / log(N₂/N₁). N ×3 → ×3, ×9, ×27.
  • Log-log plot: straight line, slope b.
  • Count ratios are exact; time ratios wobble (small N, warm-up, other processes, caches). Trust the larger N.
  • Language or machine changes a, never b.

Predicting

  • Tnew = Tlast × (Nnew/Nlast)b.
  • a = T/Nb. 3-sum: 1.050/2000³ = 1.31 × 10⁻¹⁰ s → T(4000) ≈ 8.4 s, T(16000) ≈ 538 s.
  • 2× machine: N grows 21/b (N ×2, N² ×1.41, N³ ×1.26, 2ᴺ +1 element).
  • To double N: 2b× speedup (2, 4, 8; impossible for 2ᴺ).
  • N = 10⁶ at 10⁹ ops/s: N 1 ms, N log₂ N 20 ms, N² ~17 min, N³ ~31 years.

Tilde counts

  • Total time = Σ cost × frequency. The frequency is the algorithm's.
  • Pairs ~N²/2 · triples C(N,3) ~N³/6 · 1²+…+N² ~N³/3 · 1+2+4+…+N = 2N−1 ~2N · halvings ⌊log₂ N⌋.
  • C(1000,3) = 166,167,000 exactly.
  • 3-sum: ~N³/6 if tests, ~N³/2 array accesses.
  • f ~ g implies f ∈ Θ(g), not the reverse (2N³ ∈ Θ(N³), not ~N³).

Loop shapes

  • Sum rule: sequential steps add, biggest wins. Product rule: nested work multiplies.
  • Inner bound depends on outer i → it's a sum, not a product.
  • i doubles, inner j < i → 1023 at N = 1024: linear.
  • i halves, inner j < i → ~2N: linear.
  • i·i < N → √N. Inner k < 100 → just a constant.
  • 3-sum ladder: N³ → sort + binary search N² log₂ N → two pointers N².

O, Ω, Θ as sets

  • O(g): ∃ c, n₀ > 0 with 0 ≤ f(n) ≤ c·g(n) for all n ≥ n₀. Ω: 0 ≤ c·g(n) ≤ f(n). Θ: both; Θ = O ∩ Ω.
  • 2n² + 8n + 5 ≤ c·n²: c = 15/n₀ = 1, c = 3/n₀ = 9, c = 2.5/n₀ = 17; c = 2 never works.
  • 3n² − 5n + 2 ∈ Θ(n²): c₁ = 2, c₂ = 3, n₀ = 5. ½n² − 3n: c₁ = 1/14, c₂ = ½, n₀ = 7.
  • Non-member: assume witnesses, divide, get n ≤ constant for all n. Contradiction.
  • Limit of f/g: 0 → O not Ω · constant L > 0 → Θ · ∞ → Ω not O.
  • Hierarchy: 1, log₂ n, √n, n, n log₂ n, n², n³, 2ⁿ, n!. Log base doesn't matter.
  • Mistakes: c that depends on n, checking a few values, "at least O(n²)" (meaningless; use Ω).

Memory

  • char, bool 1 · int 4 · long, double, pointer 8.
  • Member offset is a multiple of its size; total rounds up to the largest.
  • {int; Node*} = 16. {char; int; char} = 12. {int; char; char} = 8.
  • Array of N ints 4N bytes, linked list 16N: same order, 4× constant.
  • vector header 24 bytes; capacity 1, 2, 4, …, 1024; 1023 copies < 2N.
  • Aux space: 3-sum Θ(1), fact(n) Θ(n) stack, recursive binary search Θ(log₂ N), mergesort Θ(N) buffer.

Case vs bound

  • Case picks the input; O/Ω/Θ picks the set. Independent choices.
  • Insertion sort compares: best n − 1, worst n(n−1)/2, average ~n²/4 (999 · 499,500 · ~250,000 at n = 1000).
  • Running time Θ(g) ⟺ worst case O(g) and best case Ω(g).
  • push_back: one call Θ(N), amortized Θ(1). Amortized is not average.

Algorithm vs problem

  • An algorithm in Θ(f) shows the problem is in O(f): achievable, never necessary.
  • A lower bound belongs to the problem and must be proved for every algorithm.
  • Sorted search by comparisons: decision tree, 2ʰ ≥ N + 1 leaves, h ≥ ⌈log₂(N+1)⌉. Binary search's ⌊log₂ N⌋ + 1 meets it (10 at 1000, 20 at 10⁶).
  • Comparison sorting: O(N log₂ N) and Ω(N log₂ N), settled. 3-sum: O(N²) and Ω(N), open gap.
  • Classify every claim: algorithm or problem, which case, which set.
