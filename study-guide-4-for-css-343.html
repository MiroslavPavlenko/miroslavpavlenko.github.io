Tree shorthand: [20|40] is a node with two keys. "[30] over [10], [50]" means root 30 with children 10 and 50. In red-black drawings, a thick red line is a red link. Heaps are 1-based arrays (a[1] is the root) unless a question says 0-based.

1. 2-3 insert

  • 2-node: 1 key, 2 kids. 3-node: 2 keys, 3 kids. All leaves on one level.
  • Insert in a leaf. Full leaf → temp 3 keys → middle key goes up.
  • Splits can chain up. Root split = only way to get taller.
  • log₃ n ≤ h ≤ log₂ n.
  • [40] over [20|30], [60|70] + 65 → root [40|65].

2. 2-3 delete

  • Internal key → swap with predecessor (rightmost of left subtree), delete from the leaf.
  • Empty node + sibling with 2 keys → borrow: parent key down, sibling's nearest key up.
  • Sibling with 1 key → merge: parent key comes down into the sibling. Can spread up.
  • Root empties → tree shrinks one level.

3. Red-black encoding

  • [a|b] → b on top, a = red left child.
  • Decode: collapse red links into parents.
  • Rules: black root · red leans left · no node touches two reds · equal black count on every path.
  • Height ≤ 2 log₂ n. AVL ≤ 1.44 log₂ n.
  • Black height: null 0, red adds 0.

4. Red-black insert

  • New node red. On the way up, in order: right red & left black → rotateLeft · left red & left.left red → rotateRight · both red → flipColors. Root black.
  • Rotation: rising node takes the old color, the dropped node turns red.
  • Key below the 3-node: rotateRight, flip. Key above: flip. Key in between: rotateLeft, rotateRight, flip.
  • flipColors = 4-node split.

5. B-trees

  • Order M: ≤ M kids, ≤ M − 1 keys. Non-root ≥ ⌈M/2⌉ kids. Root ≥ 2 kids.
  • Split when a node hits M keys, middle goes up.
  • Height ≈ logM n. Cost = block reads.
  • M from block size: 16M − 8 ≤ block. 4096 → 256, 8192 → 512.
  • Full: Mh − 1 keys. Min (HW4): 2⌈M/2⌉h − 1. Order 3 is a 2-3 tree.

6. B+ trees

  • Records only in leaves. Leaves linked. Internal = routers.
  • Equal goes right: [30|60], search 30 → middle, 60 → right.
  • Leaf split copies up. Router split moves up.
  • Range scan: one descent, then walk the leaf chain.
  • RAM read-heavy → AVL. RAM general → red-black. Disk → B+.

7. Heap basics

  • Complete + parent ≥ children. Max at a[1].
  • 1-based: parent k/2, kids 2k, 2k + 1. Leaves ⌊n/2⌋ + 1 … n.
  • Height ⌊log₂ n⌋. 2nd largest at index 2 or 3. Min at some leaf, Θ(n) to find.
  • Sorted descending ⇒ heap. Heap ≠ sorted, heap ≠ BST.
  • Unordered array: insert 1, delMax n. Heap: log n, log n.

8. Swim and sink

  • insert: append, swim up while bigger than the parent.
  • delMax: swap root with last, shrink, sink the new root.
  • Sink swaps with the larger child. Guard j < n for a lone left child.
  • [90 80 70 30 60 50] + 85 → [90 80 85 30 60 50 70]. delMax → [80 60 70 30 50].

9. Heapify

  • Sink k = ⌊n/2⌋ down to 1. Bottom-up so both subtrees are already heaps.
  • Θ(n): sink pays height, and most nodes are near the bottom. n inserts = Θ(n log n).
  • [4 7 3 9 1 6 2] → [9 7 6 4 1 3 2].
  • [1 2 3 4 5 6 7] → [7 5 6 4 2 1 3].

10. Heapsort

  • Heapify, then: swap a[1] with a[end], sink(1, end − 1), end−−.
  • Θ(n log n) worst, Θ(1) space, not stable.
  • Min-heap with the same loop → descending.
  • [95 90 70 80 60] → round 1 [90 80 70 60 | 95], round 2 [80 60 70 | 90 95].
  • Mergesort: stable, Θ(n) space. Quicksort: Θ(n²) worst.

11. HW4: d-ary heaps and PQ uses

  • 0-based d-ary: kids d·i + 1 … d·i + d, parent (j − 1)/d. Binary 0-based: 2i + 1, 2i + 2, (j − 1)/2.
  • buildDary starts at (n − 2)/d. sinkDary picks the largest child.
  • kthLargest: min-heap of size k, pop when size > k, answer = top. n log k. Repeats count.
  • Merge k sorted lists: min-heap of one head per list, L log k.
  • std::priority_queue = max-heap (greater<int> for min). Java and Python = min-heap.
